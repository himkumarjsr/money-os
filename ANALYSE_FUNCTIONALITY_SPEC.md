## 2. State & data layers (all already shared/ported — reference only)

- **Zustand `useFinancialStore`**: holds `analysis` (live draft, written on every form change), `currentStep` (⚠️ lives in the store, not component state, on web), `lastSubmission` (last saved `FinancialProfile`), `result` (computed `AnalysisResult`), `aiPlan` (merged fix-plan + explanations), actions `setAnalysis`, `setFullAnalysis` (runs the engine), `setAiPlan`, `hydrateFromSnapshot`, `resetStore`.

- **Supabase tables**: `users.data_consent_given/at/version`, `user_analyse_snapshots` (profile + result + aiPlan + analysis, via `lib/userAnalyseSnapshot.ts`), legacy `user_analysis` (profile + `ai_fix_plan`/`ai_generated_at`, written directly by the fixplan page).

## 3. Field inventory — the 7-step form (authoritative, web source of truth)

Core shared constants (`lib/analyse-form-schema.ts`): `LIFE_STAGE_VALUES` = bachelor/married/kids/senior; `CITY_TIER_VALUES` = metro/tier2/tier3; `PRIMARY_GOAL_VALUES` = buy_home/clear_debt/retire_early/grow_wealth/kids_education/build_emergency_fund/build_insurance_premium_fund/buy_car; `UNIFIED_LOAN_TYPE_VALUES` (11: home_loan, personal_loan, car_loan, bike_loan, education_loan, pf_loan, overdraft, gold_loan, business_loan, credit_card, other); `POST_OFFICE_SCHEME_VALUES` (9: savings_account, recurring_deposit, time_deposit, nsc, kvp, mis, scss, mssc, other).

Every money/number field is coerced through `parseMoneyInput` (strips `,`/whitespace/`₹`, `undefined` for empty). Steps validate independently via `step1Schema`…`step7Schema` (each a `.pick()` of the full schema + its own `.superRefine` for cross-field rules scoped to that step only).

### Step 1 — Personal profile

`lifeStage` (enum, required) · `selfAge` (int 18–80, required) · `spouseAge` (optional, min 0) · `numberOfKids` (int 1–6, required if `lifeStage==="kids"`) · `kidsAges[]` (max 6, each required per kid count — **UI only renders cards for the first 3 kids even though up to 6 can be entered — known web limitation, decide whether to replicate or fix**) · `kidsGenders[]` ("boy"/"girl", same cap) · `cityTier` (enum, required).

### Step 2 — Income

`monthlySalary` (required, positive) · `spouseIncome` (optional, field hidden entirely if `lifeStage==="bachelor"`) · `otherIncome` (optional, "freelance, rental, business etc").

### Step 3 — Fixed obligations (loans / rent / credit card)

Toggle `hasLoans` (UI-only, not a schema field) gates the **`unifiedLoans` field array** (the real loan UI — no cap enforced in UI). Row shape:

```ts
{ id, loanType: UNIFIED_LOAN_TYPE_VALUES (default "personal_loan"), lenderName (uppercased on input),
  monthlyEMI (default 0), outstandingAmount, interestRate (0-50%, step .01),
  remainingMonths (0-360), odLimit, odUsed, odInterestOnlyYears (0-10, overdraft only),
  emiDay (1-31), emiMonth (1-12) }
```

Behaviors: "Save this loan" button (disabled until `monthlyEMI>0`) collapses a row to a read-only summary card with Edit/Remove; `loanType==="overdraft"` reveals OD-limit + interest-only-years sub-fields and relabels "outstanding" → "amount currently used"; EMI-day/month picker only appears once `monthlyEMI>0`; turning `hasLoans` off clears the whole array plus zeroes every legacy scalar via `clearLegacyLoanScalars()`.

Also on this step: `rentAmount` + `rentMaintenanceMonthly` (shown only if renting) · `creditCardBillMonthly` + `creditCardBillDay` (1–31) · legacy `additionalObligations` field array (max 6: `type`, `lenderName`, `monthlyAmount`, `outstandingAmount`, `tenureMonths`, `loanTakenYear` — superseded by `unifiedLoans` at save time, kept for back-compat only).

Live computed (not inputs): "Total monthly obligations" panel, color-coded red/amber/green vs income ratio; a red debt-warning banner appears when `fixedObligations > totalIncome * 0.5` (repeats on steps 2–4).

### Step 4 — Living expenses

Primary inputs are **aggregate totals**, not line items: `foodTotal`, `transportTotal`, `utilityTotal`, `domesticHelpTotal`, `lifestyleTotal` (all money). Granular legacy scalars (`vegetables`, `grocery`, `medicine`, `fuel`, `cabMetro`, `electricity`, `internet`, `gas`, `water`, `houseHelpMonthly`, `cookHelpMonthly`, `entertainment`, `shopping`, `personalCare`) exist in the type but are **not rendered as inputs** — they're derived from the Totals via fixed split ratios at save time (food 30/50/20 veg/grocery/medicine; transport 60/40 fuel/cab; utility 35/25/20/10 electricity/internet/gas/water; domestic help 60/40; lifestyle 40/40/20).

Conditional: `kidsSchoolFees`, `kidsActivities` (only if `lifeStage==="kids"`). `parentsSupport` (money) reveals a "Parents care" card: `parentsCity` (enum), a Yes/No "do parents have health insurance" toggle driving `parentsHealthInsuranceSumInsured` (Yes sets `max(current,500000)`, No sets 0), `parentsEmergencyCash`. Clearing `parentsSupport` to 0 resets all three.

### Step 5 — Insurance coverage

`hasHealthInsurance` (bool) → `healthInsuranceSumInsured`, `healthInsurancePremiumInput` + `healthInsurancePremiumFrequency` (monthly/yearly segmented toggle, via shared `PremiumField`), and once premium>0: renewal month+day (label changes: "renewal month & day" if yearly, "which date is it debited" if monthly). Toggling off zeroes everything.

`hasTermInsurance` (bool) → `termInsuranceSumAssured`, `termInsurancePremiumInput` + frequency, `termInsurancePremiumTillYear` (2024–2060), renewal month/day. Same on/off clearing.

Vehicle: UI-derived `hasCarInForm = carLoanEMI>0 || carMarketValue>0 || hasVehicleToggle` → `carInsurancePremiumInput`+frequency+renewal, `bikeInsurancePremiumInput`+frequency+renewal.

`hasOtherInsurance` (bool) → **`otherInsurancePremiums` field array** (max 6): `{ id, policyName, premiumAmount, frequency (default monthly), maturityAmount, maturityYear, renewalMonth, renewalDay }`. Turning on with 0 rows auto-appends one and scroll-focuses the policy-name input. Validation requires ≥1 row with `premiumAmount` set when the toggle is on (unless a flat `otherInsurancePremiumInput` exists). Static nudge: "If this is a ULIP or endowment plan, the fix plan will suggest comparing with a pure term plan."

### Step 6 — Assets and savings

Liquid: `fdValue` + `fdRate` (0–15%) + `fdMaturityYear` (auto-computes tenure) · `savingsAccountBalance` · `liquidMFValue` (+ expandable "what is a liquid MF?" educational accordion) · `otherLiquidSavings` · `medicalEmergencyFund` (optional). Live "accessible emergency fund" panel (not an input): weighted sum — savings×100%, liquidMF×95%, FD×70%, other×50% — shown with months-covered, color-coded.

`bereavementFund` (money, "last rites/travel/immediate expenses", target elsewhere is ₹2L).

Investments: `ppfBalance`, `npsBalance`, `epfBalance` · `monthlySIP` (reveals `sipAutoDebitDay` when >0) · `monthlyPPFContribution` (reveals `ppfDepositDay` when it or `ppfBalance` >0) · `totalEquityValue` (rolls up MF+stocks+US stocks+US MF+RSU into one field; the granular sub-fields exist in the type but aren't separately rendered) · **`customInvestments` field array** (max 5): `{ label, currentValue, monthlyContribution, type: equity/debt/real_estate/other }`.

Physical assets: `ownsHome` (bool) → `homeMarketValue`, `homeLoanOutstanding`, `homeLoanEMI` + EMI day/month picker. `ownsCar` (bool) → `carMarketValue`, `carLoanOutstanding`. `goldValue`, `otherAssets` + `otherAssetLabel`. Turning either ownership toggle off zeroes its dependent fields.

Ongoing contributions grid: `monthlyRD`, `monthlyPPFContribution`, `monthlyNPSContribution`, `monthlyEPFContribution`. If any girl child is under 10 (`hasEligibleGirlChild`, computed live): `ssy` (Sukanya Samriddhi) field appears with extensive helper copy; auto-resets to 0 if eligibility becomes false.

`hasPostOfficeSchemes` (bool) → **`postOfficeSchemes` field array** (max 8): `{ id, scheme: POST_OFFICE_SCHEME_VALUES (default "nsc"), amount, maturityYear }`. Auto-appends one NSC row when first toggled on; clearing resets legacy `investsInNsc`/`nscDepositAmount` scalars too.

Live "Estimated net worth" panel at the bottom (not an input) — full asset roll-up minus home/car loan outstanding.

### Step 7 — Goals

`primaryGoal` (one of 8 values, card-grid picker, required). Exactly one conditional detail group renders per selection:

- `buy_home` → `homePurchaseTarget`, `homePurchaseYear` (2024–2060) + "save 60% down payment first" note
- `retire_early` → `retirementTargetCorpus`, `retirementAge` (30–100; shows computed years-to-retirement)
- `kids_education` → `kidsEducationFundTarget` (**required if `lifeStage==="kids"`**, cross-field rule)
- `build_emergency_fund` → `emergencyFundTarget` (auto-suggests `(livingExpenses+fixedObligations)×6` the first time)
- `buy_car` → `carPurchaseTarget`, `carPurchaseYear`
- `clear_debt` / `grow_wealth` / `build_insurance_premium_fund` → no inputs, static explanatory note only

`kidsMarriageFundTarget` exists in the schema/type and is picked by `step7Schema` but **has no rendered input anywhere on web** — a dead field. Carry it in the mobile type for save-time parity but no UI obligation to add an input for it (flag to product if they want it surfaced).

## 4. Step navigation, validation & persistence mechanics (the part mobile is missing)

- **Next button**: sanitizes the current step's field-array rows in place (drops empty loan/obligation rows, coerces invalid enum values, uppercases lender names), pushes the cleaned values into the Zustand draft (`setAnalysis`) **before** validating, then runs `STEP_SCHEMAS[step].safeParse(...)`. On failure: maps every Zod field error onto react-hook-form's `setError`, plus one step-level banner message. On success: advances, animates, scrolls to top.
- **Back button**: no validation, just decrements step.
- **Progress bar**: 7 clickable pills — jumping via the bar is **not validation-gated** (only the Next button validates); short labels below highlight the current step.
- **Final submit** (step 7 only) validates **only `step7Schema`** — not a full-form re-check. Replicate this exact (lenient) behavior.
- **Live autosave**: a `watch()` subscription (active once hydrated) calls `setAnalysis(getValues())` on **every** field change, not just on Next — this is what makes the draft resumable even if the app is killed mid-step. Build the mobile equivalent as a debounced-or-immediate `onChange` → Zustand write across every field.
- **Resumability**: `detectLastStep(profile)` inspects which fields are populated (goals → assets → insurance → expenses → loans/rent → income → else step 0) to decide where "Resume" jumps to. On mount, a banner ("Continue where you left off" / Resume / Start fresh) shows if there's any saved progress; "Start fresh" wipes local caches, resets the store, and resets the form to defaults.
- **Cloud snapshot hydration**: only attempted once per logged-in user, and only if local state is genuinely empty (no `lastSubmission`, `currentStep===0`, `monthlySalary<=0`) — otherwise local/draft state always wins.
- **Money-field focus/blur UX** (reuse Tracker's established pattern — same convention): on focus, a `0`/empty value clears to `""` so the user doesn't have to backspace a zero; on blur, an empty field snaps back to `0`.
- **Lender-name text inputs are forced uppercase** as the user types, cursor position preserved.
- **Final submit sequence**: validate step 7 → merge/coalesce insurance toggles → push to draft → `normalizeAnalyseFormValues` → run the engine (`setFullAnalysis`) → **navigate to the Result screen immediately** (do not block on AI or cloud save) → fire-and-forget in the background: `getAIFixPlan`, Supabase snapshot upsert + cache-invalidate, obligation-store sync, an encrypted-backup POST. Any background failure is only logged, never shown to the user (the Result screen is already visible).

## 6. Result screen (`app/analyse/result/page.tsx`, 1124 ln) vs mobile (`result.tsx`, 222 ln)

Both render from the exact same byte-identical `AnalysisResult` object (`financialEngine.ts`'s `analyseFinances()` output) — every gap below is a **pure UI gap**, not a data gap.

`AnalysisResult` shape: `overallScore` (0–100, `=clamp(0,100, 100 - critical*15 - warning*7 - info*2)`), `criticalIssueCount`/`warningIssueCount`, `scores.{savingsRate, debtRatio, untrackedCash, emergencyFundGap}`, `flags[]`, `issues[]` (sorted by severity, deduped by code), `teaser`, `planSteps[]`, `securityChecklist[]` (up to 11 conditional items: emergency fund, medical insurance, medical emergency fund, term insurance, insurance premium reserve, SSY, post-office schemes, kids education/marriage fund, parents medical coverage, bereavement fund), `realEmergencyFund` (weighted breakdown), `termInsuranceNeeded`, `totalAssets`/`totalLiabilities`/`netWorth`, `universalBuckets` (5 categories — needs 30%/wants 5%/security(insurance) 5%/loans 40%/investment 20% of income — each with cap%, cap₹, actual₹, status).

### Web sections (top to bottom)

1. Hero gradient banner with a `SpeedoMeter` single-needle gauge + score badge (Critical <40 / Warning <70 / Good ≥70).
2. Monthly summary card: income / outflow / left-in-hand (EPF excluded from outflow, footnoted).
3. Live net worth card: assets / liabilities / net worth + a static (non-computed) percentile line.
4. "Category caps vs actual" — expandable accordion/table per bucket, itemized line items, status pills (Critical >115% of cap, Warning >100%, else Good).
5. A second, fuller `SpeedoMeter` (all 5 buckets) + 3 static tips.
6. "Financial safety net" — 5 curated checklist rows (emergency fund, medical emergency fund, term cover, health insurance, investing regularly) with ✓/⚠/✕ status + a "N of 5 in place" progress bar.
7. **Paywall teaser**: priority #1 shown free, #2–3 blurred with a lock icon, "+8 more" line, then the `PaywallModal` card (price, surplus breakdown, checklist, dynamic CTA copy keyed to score band). `handleUnlockClick` routes straight to `/analyse/fixplan` if `subscriptionTier` is pro/promax (or the `NEXT_PUBLIC_SKIP_PAYMENT` dev flag is set); otherwise opens the paywall.
8. Feedback widget, cross-sell links (tax calculator, tracker, learn), all wrapped in `AnalyseResultErrorBoundary`.

### Mobile today (explicitly self-described in-code as "Sprint 1 — full buckets/gauges/unlock land in Sprint 2")

Header + back button → colored score banner (big number, different wording: "Needs attention"/"Looking good" vs web's "Warning"/"Good") → `ResultCard` (title/subtitle + a `HealthScoreRing` — **note: this component was not found anywhere in the repo; verify it exists/builds before relying on it**) → up to the first 8 `issues` rendered as flat `IssueCard` rows (no expand, no bucket breakdown) → "View fix plan →" (unconditional, no entitlement check) / "Retake health check".

**Completely absent on mobile:** bucket/category table, net worth summary, monthly income/outflow summary, the 5-item safety-net checklist, any gauge beyond the score ring, the paywall/teaser mechanism, analytics events, cross-sell links, the error boundary.

### 7.1 Real AI contract (confirmed by reading `app/api/ai/analyse/route.ts` directly — treat this as the source of truth over `lib/finkoinAiPlan.ts`, which appears to target a different/legacy surface)

`POST /api/ai/analyse` with `{ profile, analysis }` (bearer-authed, rate-limited to 10/hour/user). Server runs `buildPriorityPlan(profile, analysis)` itself, retrieves RAG knowledge chunks, and prompts Groq (`openai/gpt-oss-20b` by default) with a strict system prompt ("use the engine's numbers exactly, never invent closed gaps, every field must cite real ₹ amounts"). Returns:

```ts
{ priorityPlan: PriorityPlan,  // same shape as buildPriorityPlan's own output
  explanations: {
    greeting, overallSummary, debtStrategy, goalAdvice,
    thisWeekAction, in12Months, encouragement, disclaimer,
    priorityExplanations: { [priorityId: string]: string }  // per-item AI copy, keyed by id e.g. "emergency_fund"
  },
  knowledgeUsed: string[],
  isFallback?: true }  // present when Groq/JSON-parsing failed — server falls back to its OWN rule-based explanations (not lib/finkoinAiPlan.ts's buildFallbackFinkoinPlan — that function targets a different contract shape and is likely unused by this flow)
```

**Mobile must call this same endpoint** — do not reimplement the AI logic client-side; it's a server route.

### 7.2 Client merge logic (`mergeEnginePriorityPlan`, port verbatim)

Every numeric field (gap, monthlyContribution, rank, surplus before/after, debts, goals, income, surplus, monthlyPlan, scores) is **always** taken from the engine's own fresh local `buildPriorityPlan(profile, result)` call — never from the server response — specifically so a stale/cached AI response can never resurrect a closed gap. Only `title`/`instrument`/`whyThisMatters` _may_ come from the AI response's `priorityPlan.priorities[i]` matching by `id` (same engine shape), and **only while that item is still open** (`gap>0 && monthly>0 && status!=="complete"`); once closed, hardcoded "maintain this completed bucket" text wins regardless of what AI/cache says. `actionThisWeek` is **always** the engine's own text — the overlay's version is never read (replicate this bug-compatible behavior unless product wants it fixed). `monthsToComplete` is always recomputed client-side via `monthsForPriority(id, gap, monthly)` (`1` for `term_insurance`/`health_insurance` since those are one-time purchases, else `ceil(gap/monthly)`), never trusted from either source.

A second guard, `reconcileExplanations`, regenerates `overallSummary`/`goalAdvice`/`greeting` from a template if the cached text mentions a bucket (e.g. "medical") that the engine now considers closed — belt-and-suspenders against stale AI copy independent of the numeric merge.

### 7.3 Caching (`lib/cache.ts` — port to AsyncStorage/MMKV; **completely absent on mobile today**)

Single-slot cache (one JSON blob per device, not per-profile — only the most recent plan is ever kept), 30-day TTL. Two independent invalidation checks must both pass for a cache hit: (1) `hashProfile(profile, analysis)` unchanged (djb2 hash over profile + `{overallScore, scores, termInsuranceNeeded, realEmergencyFundTotal, issueCodes}`), and (2) `enginePlanFingerprint(plan)` unchanged (a separate coarser hash over the engine's own priorities/goals/surplus — catches the case where an app update changed the deterministic math even though the user's raw inputs didn't). On cache hit: merge engine with the cached AI overlay, no network call. On miss/stale/forced: call the API, cache the result, keep showing the existing plan on screen while refreshing in the background (never flip back to a full-screen loader except on the very first load ever).

A silent auto-retry fires once, 5 seconds after any load that returned `isFallback:true`, without disrupting the visible UI.

### 7.4 `buildPriorityPlan` output (already ported, byte-identical — just consume it)

`PriorityItem[]` (rank, id, title, category, urgency critical/high/medium, status missing/partial/complete, currentAmount/targetAmount/gap, monthlyRequired/monthlyContribution, surplusBefore/surplusAfterThis, monthsToComplete, instrument, actionThisWeek, whyThisMatters, icon, canBuyFromFinkoin) in a strict waterfall order: emergency fund → medical emergency fund → term insurance (if gap>0) → health insurance (if gap>0) → SSY (per eligible girl child) → one goal-deploy item keyed to `primaryGoal`. Plus `debts[]` (avalanche-ordered, with `extraEMIRecommended` and an amortization-estimated payoff timeline), `goals[]` (always just the one matching `primaryGoal`), `monthlyIncome`/`monthlySurplus`/`surplusBreakdown`, `scoreToday`/`scoreAfter12Months` (gain = `critical*15+high*8+medium*4` capped, applied at 70% realism factor), `topAction`, optional `fdSuggestion` (if the user's stated FD rate is >0.5pp below a hardcoded best-rate table), optional `monthlyPlan[]` (a 12-row month-by-month simulation).

### 7.5 Screen layout to build (mirror web's structure)

Hero summary banner → collapsible surplus breakdown → one card per open priority (rank badge, urgency-colored border, gap/monthly/timeline grid, "where to invest", "why this matters", green "this week" action box) → surplus allocation summary (step-by-step deduction to a remaining buffer) → 12-month month-wise table → debt payoff cards (avalanche order, extra-EMI callout with months-saved) → single goal progress card → score-today→score-in-12-months projection → optional FD-switch suggestion card → "do this first" + encouragement callouts → PDF download button → disclaimer footer.

**Known web quirk to decide on, don't silently inherit without a decision:** the `visiblePriorities` filter excludes `term_insurance`/`health_insurance` ids from the generic card loop (they're meant to have bespoke dedicated UI "elsewhere" that, on inspection, doesn't actually exist in the rendered output) — meaning on web today, term/health insurance priorities **never actually render as a card at all**, despite dedicated JSX branches existing for them. Mobile should either replicate this (bug-compatible) or — better — fix it so term/health cards render like every other priority.

### 7.6 Auth/entitlement gating (must replicate)

Unauthenticated → redirect to login. Authenticated but not `pro`/`promax`/admin tier → redirect to Result screen (where the paywall lives) unless a dev bypass flag is set.

### 7.7 Loading/error UX

Rotating cosmetic loading messages ("Reading your profile...", "Calculating insurance gaps...", "Building debt strategy...", "Generating 12-month roadmap...", "Almost ready...", 2.5s interval) shown only on the very first load. Error state on web today is a bare unstyled message with **no retry button** — recommend mobile improve on this with an explicit "Try again" CTA that calls the load function with `forceRefresh=true`, since web's own hard-error path has no recovery other than navigating away and back.

## 9. PDF export (`lib/generatePDF.ts`, 904 ln) — needs a platform decision, not a line-for-line port

Web generates an 11-section PDF **entirely client-side** with `jsPDF` (hand-drawn rects/circles/triangle-fan pie charts/text, no HTML-to-canvas, no server call) and triggers a browser download via `doc.save()`. Content: cover page (score banner, income-split pie chart, monthly summary, top-3-this-week), corrected net-worth/budget-allocation tables, income-to-surplus waterfall, priority-by-priority detail pages, debt-clearance strategy + computed interest saved, 12-month action plan with 4 phase blocks, goals + score projection, a 12-month checklist, a monthly-allocation bar chart, and a final disclaimer page — all built from the same `profile`/`result`/`priorityPlan`/`explanations` objects already available on the Fix Plan screen, plus a `phases`/`keySnapshot` object constructed inline by the page itself (not part of `generatePDF.ts` — must be ported too, ~115 lines of page-level logic).

**`doc.save()` has no React Native equivalent.** Options to decide between before building:

1. Port the jsPDF drawing code using a React-Native-compatible PDF library (e.g. `react-native-html-to-pdf`, a WebView-hosted jsPDF shim, or `react-native-pdf-lib`), then hand the resulting file to the OS share sheet (`Share.share` / `react-native-share`) instead of a browser download.
2. Move PDF generation server-side (new work on both platforms — nothing does this today) and have mobile simply download/share the resulting URL — likely far less effort than replicating 904 lines of hand-drawn jsPDF layout natively, at the cost of a new backend endpoint.

This spec recommends **option 2** given the effort delta, but defer to whoever scopes the sprint — either way, this is additional backend/infra work, not a pure mobile port, and should be called out as its own ticket.

## 10. Build order recommendation (for the Cursor prompt / sprint planning)

1. **Form validation & persistence engine first** (step-gated Zod validation on Next, `detectLastStep` resume, live autosave-on-every-change into Zustand) — this is foundational; every other fix depends on the form actually producing correct, resumable `FinancialProfile` data.
2. **Close the 4 missing field arrays** (loans/`unifiedLoans`, other-insurance, post-office schemes, custom investments) plus the Goals step's amount/timeline fields and the insurance premium-frequency toggle that currently has no UI despite existing in state. These are the field-sync gaps that most directly cause mobile users' saved profiles to be thinner than web's.
3. **Result screen rebuild**: bucket table, net worth card, monthly summary, 5-item safety net checklist, error boundary. (All data already available from the identical engine — pure UI work.)
4. **Paywall**: a mobile Razorpay (or platform-appropriate IAP) unlock flow gating Fix Plan access, mirroring web's ₹99/one-time copy and bullets.
5. **Fix Plan screen**: wire `/api/ai/analyse`, port `mergeEnginePriorityPlan`/`reconcileExplanations`, build the AsyncStorage cache per §7.3, build the screen layout per §7.5.
6. **PDF export**: scope as its own ticket once a platform strategy (§9) is chosen.
7. **Polish**: step animations, the advisor-modal chrome (optional/low-priority), `StepIndicator.tsx` actually wired into the live form (it's built but currently orphaned).

Everything in `lib/*.ts` referenced throughout this doc is already correctly ported and byte-identical — no business-logic work is needed anywhere in this list; it is 100% UI/screen work plus the two new infra pieces (AI cache storage, PDF strategy).
